## Bağlam

Bu bölümle birlikte kod dört Maven modülüne ayrıldı. Katmanlar *(api, application, domain, persistence)* ayrı Maven modülleri değil, `sales` modülü içindeki paketlerdir *(package-by-feature)*. Bu tercih bir iş değişikliğinin tek modülde kalmasını sağlar ancak bir bedeli vardır: Maven bağımlılıkları yalnızca modül *(JAR)* sınırında denetler. Aynı JAR içindeki iki paket arasında `import` yazmayı hiçbir derleyici kuralı engellemez. Erişim belirleyicileri de *(public, package-private)* tek başına çözüm değildir, zira katmanlar arası çağrıların büyük kısmı zaten `public` tipler üzerinden yapılır. Kural yalnızca kod incelemesine bırakılırsa ilk acil iş sırasında delinir ve büyük ihtimalle fark edilmez.

## Karar

Paketler arasındaki izinli bağımlılık yönleri aşağıdaki matriste tanımlanmıştır. Satır bağımlılığı kuran paketi, sütun ise bağımlı olunan paketi ifade eder.

| **Kimden/Kime (->)** | **domain** | **api** | **application** | **persistence** | **shared-kernel** |
| --- | :---: | :---: | :---: | :---: | :---: |
| **domain** | - | X | X | X | Ok |
| **api** | X | - | X | X | Ok |
| **application** | Ok | Ok | - | Ok | Ok |
| **persistence** | Ok | X | X | - | Ok |
| **shared-kernel** | X | X | X | X | - |

Matrisi şöyle okuyabiliriz;

- **domain** hiçbir sales paketini görmez. Modelin merkezi odur ve bağımlılıklar her zaman ona doğru akar.
- **api** dışarıya verilen sözleşmedir *(record'lardan oluşan DTO'lar)*. Domain tiplerini görmemesi, domain değiştiğinde dış sözleşmenin kendiliğinden değişmemesini sağlar. İkisi arasındaki çeviriyi application paketindeki `OrderMapper` yapar.
- **application** orkestrasyon katmanıdır ve diğer tüm paketleri görebilir. Matristeki hiç `X` içermeyen tek satır budur.
- **persistence** domain nesnelerini saklar ama onları kimin, hangi rapora dönüştürdüğünü bilmez.
- **shared-kernel** hiçbir iş modülünü görmez. Bu yön tek yönlüdür ve kalıcıdır.
- Matris döngüye izin vermez. `Ok` işaretlerini takip ederek bir paketten çıkıp aynı pakete geri dönmek mümkün değildir.

## Değerlendirilen Alternatifler

| **Alternatif** | **Neden seçilmedi?** |
| --- | --- |
| Her katmanı ayrı bir Maven modülü yapmak *(sales-domain, sales-api vb.)* | Bağımlılık yönünü derleyici korurdu ancak *siparişe indirim ekle* gibi tek bir iş değişikliği birden fazla modülü birlikte değiştirmeyi gerektirirdi. Modül sayısı da iş modülü sayısı ile çarpılarak büyürdü *(6 iş modülü x 4 katman = 24 modül)*. |
| Java Platform Module System *(JPMS, module-info.java)* | Bir modülün hangi paketleri dışarıya açtığını *(exports)* kontrol eder ama aynı JPMS modülü içindeki paketler arasındaki yönü ifade edemez. Ayrıca derleme ve test yapılandırmasını karmaşıklaştırır. |
| Yalnızca kod incelemesi *(code review)* | Ucuzdur ama tekrarlanabilir değildir. İhlalin yakalanması incelemeyi yapan kişinin dikkatine bağlıdır. |

## Sonuçlar

- **Olumlu:** Bir iş değişikliği tek Maven modülünde kalır ve paket yapısı iş alanını yansıtır. Paketler arasındaki yön her `mvn test` çalıştırmasında doğrulanır, ihlal build'i kırar.
- **Olumsuz:** Kural derleme zamanında değil test zamanında yakalanır. IDE yasak bir `import` satırı yazılırken uyarı vermez.
- **Risk:** `OrderRepository` arayüzü persistence paketinde durduğu için application paketi persistence'a bağımlıdır. Hexagonal mimaride bu arayüz bir *port* olarak domain tarafında yer alırdı. Bu tercih ilerleyen bölümlerde yeniden değerlendirilebilir.

## Doğrulama

| **Matris kuralı** | **Kim korur?** | **Kural** |
| --- | --- | --- |
| domain ↛ api, application, persistence | ArchUnit | `domain_does_not_see_other_layers` |
| api ↛ domain, application, persistence | ArchUnit | `api_is_a_pure_contract` |
| persistence ↛ api, application | ArchUnit | `persistence_only_sees_domain` |
| shared-kernel ↛ sales | Maven + ArchUnit | Modül bağımlılık grafiği ve `shared_kernel_depends_on_no_business_module` |

Son satırdaki çift koruma bilinçlidir. Maven bu yönü modül düzeyinde korur; `shared-kernel`'in pom dosyasına `sales` bağımlılığı eklenirse reactor döngüsel bağımlılık hatası verir. ArchUnit kuralı ise paket düzeyinde çalışır. Birisi `sales` modülü içinde `..shared.kernel..` paketine bir sınıf koyup sales tiplerini kullanırsa Maven bunu göremez ama kural yakalar.
